# Milestone 11 — Validation & Portfolio Release

## Release status
CIP Intelligence V1 is **portfolio-complete** as a simulated, read-only industrial analytics application. It is not represented as microbiological proof of cleanliness, an autonomous CIP controller, a validated sanitation-release system, or a production-certified food-safety product.

## M11 facility-scale synthetic validation campaign
M11 runs a seeded, reproducible known-answer campaign against the same reconstruction, L2 compliance, and L3 behavioral engines used by the application.

The release campaign uses **four independent synthetic HTST circuits**. Each circuit deliberately uses the same development-only HTST validation fixture so the software behavior can be compared under controlled conditions. This is not a claim that unlike dairy equipment should share one CIP recipe.

- Synthetic circuits: **4**
- Historical baseline cycles: **240** (60 per circuit)
- Later evaluation cycles: **2,000**
- Total cycles exercised: **2,240**
- All simulator recipe values remain development fixtures, not universal dairy CIP recommendations.

## Important M11 fixes discovered during release validation
M11 did not simply rerun old tests. It exposed and corrected three release-quality issues:

### Operational audit-store recovery
The long-lived API could fail after its local SQLite runtime directory was externally removed/recreated. The operational store now recreates its parent/schema lazily and the behavior is regression-tested.

### Validation throughput accounting
The first M11 harness incorrectly used an old baseline-count constant in the performance calculation. The harness now derives throughput from the actual frozen baseline size.

### Nominal simulator endpoint determinism
A larger campaign found one nominal synthetic cycle where random final-rinse noise prevented the configured 30-second endpoint hold. The simulator was corrected so known-answer non-fault scenarios deterministically establish the approved synthetic endpoint; random noise remains available for behavioral statistics rather than silently changing the scenario label.

None of these corrections weakens plant-data gating or compliance logic.

## What V1 demonstrates
1. Read-only acquisition and immutable source lineage.
2. Conservative data-quality gating.
3. Explicit/inferred CIP reconstruction with evidence grades.
4. Deterministic validated-recipe compliance separate from diagnosis.
5. Asset/recipe-specific behavioral baselines with anti-leakage controls.
6. Resource/economic accounting without treating recirculation as water consumption.

9. Controlled optimization candidates subordinate to plant validation/change control.

## What the large M11 campaign does *not* validate
The 2,240-cycle campaign intentionally concentrates on reconstruction, L2 compliance, and L3 behavior at scale. L0, L4, L5, and L6 contracts are covered by targeted regression tests, but they do not yet have real-world sensitivity/precision estimates.

M11 also does not establish:

- microbiological cleanliness;
- sanitation-release suitability;
- real-plant false-positive/false-negative rates;
- cross-plant diagnostic generalization;
- vendor-specific historian/OPC UA/LIMS/MES/CMMS compatibility;
- savings claims for a real dairy facility.

## Real-plant validation plan
The next phase is deliberately outside portfolio V1:

1. Obtain one anonymized historical circuit dataset, ideally 3–12 months.
2. Load the plant's actual approved CIP recipe/validation limits, tag mappings, units, and calibration context.
3. Run CIP Intelligence offline/read-only with no control connection.
4. Blind-score known historical events where possible.
5. Measure detection sensitivity, false-positive rate, diagnostic precision, confidence calibration, data coverage, and economic findings.
6. Review results with plant engineering and QA before any operational conclusion.
7. If retrospective performance is acceptable, conduct a shadow-mode prospective pilot.
8. Only after controlled plant validation should optimization findings be considered for formal plant change control.

## Release boundary
CIP Intelligence V1 is a serious engineering portfolio prototype and **pilot candidate**, not a commercial plant-certified product. A commercial deployment still requires vendor-specific connectors, customer OT/cybersecurity review, identity/PKI integration, validated plant configuration, backups/observability, incident procedures, and real-world performance evidence.
